# ADR-006 — Review project instructions before previewing an additive install

**Status** Proposed under [A2.3](https://github.com/DRAGGON-Lab/ANDES/issues/24). Builds on [ADR-004](ADR-004.md) and [ADR-005](ADR-005.md).

## Decision

Separate the host and path check from the installation preview. Bind the preview to a local verified artifact, an observed supported Codex host, and an unoccupied project-local namespace. Treat native settings outside the baseline as requiring review. Preserve the existing project instructions as an exact suffix when the owner confirms a compatibility review tied to both those bytes and the pinned policy.

Review arbitrary Markdown through the ANDES workflow with explicit human confirmation. Fixed string rules would miss paraphrases and misclassify examples. An automatic merge would give a planner write authority and could displace project guidance. Preview the additive block with an exact expected prior digest so a later writer can detect changes.

## Consequences

The first supported configuration is intentionally narrow. Existing root instructions can refine project practices, with additional global or nested context requiring separate verification. A2.4 must reverify and obtain approval before applying changes. Revisit this boundary when accepting additional Codex versions or instruction scopes, or introducing managed ownership and updates.
