# ADR-005 — Pin and resolve closed local release artifacts

**Status:** Accepted by the maintainer on 2026-11-28 under [A2.2 / #19](https://github.com/DRAGGON-Lab/ANDES/issues/19). Implementation baseline `05f371213390f68471728f7a464433f5a8bbcadb`. Extends [ADR-002](ADR-002.md) and [ADR-004](ADR-004.md).

## Decision

Use a draft 2020-12 manifest and an exact release identity with a caller-trusted SHA-256 of the raw manifest. The manifest binds local inventory, catalog, source metadata and adapter constraints. Verify all bytes in a closed, unpacked directory using descriptor-relative reads and exact path membership. Compose the pinned catalog with the accepted selection rules. Emit a deterministic JSON resolution for A2.3. The [release contract](../release-contract.md) defines the inputs, refusal cases and handoff.

An external manifest digest gives reviewers a single value to record and compare. It covers the complete inventory through the manifest. A match establishes byte identity under that trust model. The maintainer still verifies source attribution and permissions and approves the specific release identity.

## Alternatives

| Option | Tradeoff |
|---|---|
| Discover a moving tag or branch | Convenient selection would depend on time and remote state. Reviewers could resolve different bytes from the same request. |
| Pin the commit or catalog alone | A commit attributes source and a catalog defines composition. An independently assembled local artifact needs a digest that binds its payload, metadata and inventory together. |
| Adopt signed archives or a registry immediately | Signatures and transport could extend distribution, with key ownership, trust policy, extraction and availability decisions. The current slice needs only a trusted local snapshot and pin. |

## Consequences and validation

V1 uses the existing Python and JSON Schema dependencies. Users obtain the artifact and pin separately. Spelling, case, file type and link rules constrain portable packaging. The resolver reads unselected files too so a successful resolution identifies the whole snapshot. It hashes opaque payload files without executing them and holds parsed records' verified bytes in memory. The caller supplies a stable snapshot and must reverify the bytes before later use.

The candidate's adapter tuple reflects the bounded ADR-004 evidence. A2.3 owns actual host detection, projection, path ownership and target conflict checks. Revisit this decision if a second adapter, another supported host tuple, signed distribution, or a stronger snapshot boundary becomes necessary. The [verification packet](../evidence/a2-2.md) records the behavioral evidence and independent review.
