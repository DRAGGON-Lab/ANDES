# ADR-003: Read-only foundation CI and offline secret checks

Status: proposed A1.4 implementation for maintainer acceptance. Date: 2026-11-27.

## Decision

Use GitHub Actions for the existing Python checks, with full-SHA pinned checkout/setup actions, pinned uv and locked dependencies. Keep workflow permissions read-only and omit stored Git credentials, caches, secrets and privileged events. Record settings observations separately from a proposed human review rule plan; do not apply administrative changes.

Use detect-secrets 1.5.0 as a development-only library, limited to explicit offline pattern plugins plus the standard reviewed-inline-allowlist filter. The wrapper emits locations/types only, rejects scanner errors, and suppresses third-party diagnostics. Exclude entropy detectors because immutable source/artifact hashes are expected throughout this repository; no blanket baseline is generated.

## Alternatives and consequences

A hand-written collection of token regexes would duplicate established detectors. A hosted scanning action adds another runtime/trust dependency, and online token verification creates unnecessary network/credential handling. Gitleaks CLI remains an alternative if broader coverage is needed; it is not installed or implied by this task.

Pattern detection has false positives and false negatives; no confidentiality guarantee is made. Review scanner/annotation changes independently. Candidate tests cannot enforce their own protection policy, so actual human PR rules remain a separate administrative boundary. Source/license review remains necessary independently of secret scanning.

The upstream package source is [Yelp/detect-secrets v1.5.0](https://github.com/Yelp/detect-secrets/tree/01886c8a910c64595c47f186ca1ffc0b77fa5458); its Apache-2.0 LICENSE was inspected. The package is installed as a dependency with its distribution notices, not vendored/relicensed as ANDES text. Exact package and transitive artifact hashes are in uv.lock.

The checked action revisions are actions/checkout `11d5960a326750d5838078e36cf38b85af677262` (v4) and astral-sh/setup-uv `37802adc94f370d6bfd71619e3f0bf239e1f3b78` (v7), resolved through GitHub GET. The setup action's inputs were inspected for pinned version, Python selection, disabled caching and empty download token. These pins do not constitute a code audit of the actions.

## Validation and revisit

Validate good/bad fixture exit statuses, secret rejection/redaction and error behavior locally; inspect permissions and triggers; independently review the exact candidate. Hosted execution remains not_run until publication. Revisit on a supported-platform failure, relevant dependency advisory, unacceptable false-positive/negative pattern, or a need for binary/history scanning. Broader coverage or authority requires a reviewed change.
