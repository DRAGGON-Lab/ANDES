# ANDES repository instructions

Start with [CONSTITUTION.md](CONSTITUTION.md) (normative requirements), [AGENT.md](AGENT.md) (coordination, task contracts and verification), and [PRODUCT.md](PRODUCT.md) / [ARCHITECTURE.md](ARCHITECTURE.md) for relevant context. Consult [design baseline](docs/design-baseline.md), applicable ADRs and the approved task. Load additional material only as needed.

- Verify repository identity, exact revision, current instructions and dirty state; preserve unrelated changes. Do not infer that planned modules or commands exist.
- Work only on the authorized scope with frozen acceptance criteria, proportionate rigour and evidence. Report unknowns and blockers; never fabricate test or research results.
- Prefer small behavior-verified changes, independent review for L2/L3 and evidence-bearing handoffs. Follow the public/private and release boundaries in [CONTRIBUTING.md](CONTRIBUTING.md).
- The A1 foundation and A2.1 spike are accepted; use the existing local/hosted checks in [development workflow](docs/development-workflow.md). There is no production installer or released ANDES product. Use the task's granted authority; these files do not grant publication, administrative changes, protected merge or release authority.

This is a compact discovery entry; [AGENT.md](AGENT.md) is the detailed coordination guide. See [foundation closeout](docs/evidence/foundation-closeout.md) for acceptance and [native compatibility](docs/codex-compatibility.md) for the bounded macOS evidence. Native implicit routing, successful model inference, relative-reference following, role execution, production installation and broader native platform support remain unverified.
