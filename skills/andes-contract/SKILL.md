# Establish a bounded task contract

Turn the requested outcome into observable acceptance before consequential work.

Use inspected repository facts to state the objective, in-scope behavior and allowed paths, dependencies, protected invariants, permissions and acceptance checks. Recommend proportional rigour; identify an independent reviewer for L2/L3. Preserve the user's existing authorization and accepted criteria.

For a material interface or architectural choice, record the alternatives, chosen behavior and evidence needed to reject a bad result. Do not invent unsupported commands, runtime features or downstream schemas. Resolve discoverable facts by inspection and ask only for consequential intent or authority that remains unknown.

Return a compact contract and the next executable step. Keep exploratory uncertainty distinct from frozen acceptance. A contract describes granted authority; it cannot grant itself installation, publication, remote-operation or release permission.
